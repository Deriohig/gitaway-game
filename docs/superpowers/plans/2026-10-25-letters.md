# Letters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Barnaby's ten field notes arrive as letters in the morning post every few days once he has settled, and are read in Journal → Letters. The cut residents are removed.

**Architecture:**
- **Content:** the notes live as parts in `src/game/content/letters.ts`.
- **Delivery:** `advanceMail` in `src/game/systems/mail.ts` is a pure step in `advance()`'s table, guarded by a cheap `DUE.mail` check. It delivers at most one letter per post time (08:00 local), using one saved cursor, `mail.checkedAt`.
- **UI:** the Letters tab, inside the existing Journal panel, appears once a letter has arrived.

**Tech Stack:** TypeScript, React, zustand, vitest (`TZ=UTC vitest run`), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-24-letters-design.md`. Read it first. Where this plan and the spec differ, the ruling below says why.

## Rulings

- **R1, a cursor field.**
  - **Decision:** add `mail.checkedAt: number | null`, the last post time considered. The spec allowed for this ("adds the smallest field that is and says so").
  - **Why:** the spec's "previous advance" time doesn't exist in state.
  - **Cost if wrong:** one extra field.
- **R2, guarding against a chunked catch-up.**
  - **Decision:** at most one letter arrives after `seenAt`. Each advance considers only the latest post time, and no letter arrives while one already has `at > seenAt`.
  - **Why:** production catch-up is one `advance` call, so the waiting letter carries the latest post time, as the spec says. If catch-up were ever split into steps, the guard holds it to one letter, but that letter would carry the first crossed post time instead.
  - **Cost if wrong:** a cosmetic stamp difference on a path production doesn't take.
- **R3, the tab filter's argument.**
  - **Decision:** `journalTabs(lettersArrived = false)`. The no-argument form keeps hiding Letters.
  - **Why:** `e2e/journal.spec.ts:346` counts tabs with no state.
  - **Cost if wrong:** none.
- **R4, the journal line's time.**
  - **Decision:** the letter's `at` and its journal line both use `eventTime(s, post, now)` from `journal.ts`.
  - **Why:** it equals the post time except when that would sit at or before `seenAt`, which would drop it from the recap.
- **R5, older dates.**
  - **Decision:** older letters show "24 October" (`toLocaleDateString('en-GB', { day: 'numeric', month: 'long' })`), not the journal's weekday form.
  - **Why:** the spec says so. (The "Thursday" note's wording was later made true on any day, so it doesn't depend on this.)

## Review Focus

1. **A farm name containing `$&` or `{farm}`** prints literally in the salutation. The test is in Task 2.
2. **A save with a letter `at`, or a `checkedAt`, in the future** (the clock was ahead, then corrected) must not stall the post forever. Sanitize clamps a future `at` to `now` and drops a future `checkedAt`. The test is in Task 3.
3. **A player who updates with Barnaby settled long ago** gets exactly one letter on first load, not a backlog. The test is in Task 3.
4. **`letters` on with `characters` off** must deliver nothing and not throw. The test is in Task 3.
5. **The Letters tab's accessible name and text never contain a digit or count,** with several unread letters. The test is in Task 4's e2e.

    - `readLetter(state: GameState, id: LetterId): Result`;
    - `hasUnread(s: GameState): boolean`;
    - `lettersForTab(letters: readonly Letter[]): Letter[]`: unread first, then newest first.

**The delivery algorithm**, which the tests pin but don't fully determine:

```
mailDue(s, now):
  due = letterDue(s); if due === null → false
  if s.mail.letters.length === LETTER_IDS.length → false
  P = latestPost(now)
  return P >= due && (s.mail.checkedAt === null || P > s.mail.checkedAt)

advanceMail(s, now, out):
  if !mailDue(s, now) → false
  P = latestPost(now); s.mail.checkedAt = P
  if some letter has at > s.seenAt → true                     // R2: one waits, at most
  ids = unlockedNotes(s, P); if ids is empty → true           // silent; tried again at the next post
  id = pickNote(ids, P, sent ids); at = eventTime(s, P, now)
  s.mail.letters.push({ id, at, read: false })
  write(s, 'letter', `A letter from ${LETTER_SENDERS[LETTERS[id].from].name}.`, undefined, at)
  return true                                                  // no notice pushed to out
```
