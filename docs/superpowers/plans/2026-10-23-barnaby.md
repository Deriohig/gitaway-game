# Barnaby, the shiver and the characters system: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to carry out this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

- **Goal:** Barnaby Wick is found the morning after level 6, camps beside the garden, and moves into the highland ruin. The island shivers when work is done. All of it is built on a small characters system that Síofra and Fin will reuse.
- **Architecture:**
  - **Save:** a new `characters` save slice holds the latest shiver and Barnaby's state.
  - **Advance:** an advance step, `characters`, finds him at the morning due time and writes his land lines.
  - **Shivers:** engine actions call `shiver()` when work is credited, which also writes his capped remark.
  - **World:** one feature component draws him, his camp and the ruin with stand-ins, and shows his tap line.
  - **Shiver gust:** a driver turns the latest shiver into a gust travelling through the wind shader.
- **Tech stack:** TypeScript, React 19, React Three Fiber and drei, zustand, Vitest, Playwright. The repo is in WSL.
- **Where:** worktree `/home/me/Projects/gitaway-wt/characters`, branch `feat/characters`, off main `8d0306f`.
- **Spec:** `docs/superpowers/specs/2026-10-22-barnaby-design.md`. Read it first; its appendix holds every line of copy.

## Global constraints

**Rules from the spec:**
- **Copy is verbatim from the spec's appendix.** Titles are at most 160 characters and details at most 300.
- **Characters and shivers never change coins, wood or XP.** `npm run balance` must still pass T1–T7.
- **No counts anywhere in the UI.** Nothing shows how many shivers, lines or days.
- **Guardrails:**
  - nothing decays or expires;
  - no streaks;
  - story text never explains why the island grows;
  - he mentions a shiver only right after one.
- **The `characters` feature is on by default.** Switched off, nothing is drawn, written or shivered, but a saved `characters` slice is kept as it is.
- **No `SAVE_VERSION` bump.** The new slice is sanitized with defaults.
- **Barnaby's journal lines use the new journal kind `character`,** which is recapped.
- **Shiver sizes:** `big` when a session ends with credited minutes; `small` for a logged task, or a commit report that credits at least one commit and is live.
- **Live commit:** `realNow - latest * 1000 <= LIVE_COMMIT_MS`, where `LIVE_COMMIT_MS = 10 * 60_000` and `latest` is in seconds.

**Process:**
- **Commands:** run in WSL from script files, each starting with `. ~/.nvm/nvm.sh`.
- **File ownership:** files written through `\\wsl.localhost` end up owned by root, so `chown $USER:$USER` them.
- **Tests:**
  - unit tests run with `TZ=UTC npx vitest run`, and the typecheck is `npx tsc -b`;
  - for e2e, CI runs desktop; run `npm run e2e:mobile` locally before pushing app changes, with a distinct `E2E_PORT`.
- **TDD:** every behaviour's test is seen failing first.
- **Git:**
  - never `git add` `art/` or `public/models/`;
  - commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, and docs-only commits carry `[skip ci]`;
  - one branch, one PR at the end; never merge.

## Spec clarification

Spec §3 says once-only lines are recorded as journal `told` ids in `STORY_IDS`. Spec §6 puts `told` inside Barnaby's own slice. This plan follows §6: his once-only lines are tracked in `characters.barnaby`, and `STORY_IDS` is untouched. This keeps all character state in one sanitized slice.

## Review focus

1. **A farm crossing 06:00 in existing e2e specs.** `establishedFarm` is level 7, so any spec that waits past the next 06:00 now meets Barnaby, with a toast and a journal line. Expected: no existing spec breaks for an unrelated reason. Pinned in Task 2's full e2e run, which fixes any collision by setting `characters.barnaby.stage` in that spec's save, not by weakening the spec.
2. **Buying the highland after he's due but before he's found,** in the same catch-up. Expected: he goes straight to the ruin, writing "found" and then "straightToRuin", with no separate highland land line. Pinned in Task 2.
3. **The clock steps back after he's found.** Expected: his stage never goes back to `away`, and he is never found twice. Pinned in Task 2.
4. **A day with many shivers** (12 tasks, commits, two sessions). Expected: exactly one remark that day. A shiver arriving mid-gust restarts the gust without stacking past the big peak. Pinned in Tasks 3 and 6.
5. **The switch is off with a saved, found Barnaby.** Expected: nothing is drawn or written and the slice survives a save round-trip. Turning the switch back on restores him. Pinned in Task 1.

**Behaviour** (an exact list, since the tests pin each line):
1. **Scheduling:** stage `away`, `dueAt === null` and `levelForXp(s.xp) >= ARRIVAL_LEVEL` sets `dueAt = nextMorning(now)`.
2. **Being found:** stage `away` and `now >= dueAt`:
   - `foundAt = dueAt`;
   - `sawLand` = every land piece owned now (they get no line);
   - a toast notice `{ kind: 'info', title: found.toast, journal: false }` goes to `out`;
   - `write(s, 'character', found.title, found.detail, dueAt)`.
3. **Then, the stage:**
   - if `owned.highland > 0`: stage `ruin`, `movedAt = dueAt`, and `write(… straightToRuin …, dueAt)`;
   - otherwise stage `camp`.
4. **Land lines:** stage not `away`, for each owned land piece not in `sawLand` (in `LandPiece` order): add it to `sawLand` and `note(s, out, { kind: 'info', journal: 'character', quiet: true, title, detail }, now)` with `BARNABY.land[piece]`. For `highland` while camping, also set stage `ruin` and `movedAt = now`.
5. **The stage never goes backwards.** Nothing sets `away` once found.

### Task 6: The shiver in the world

**Files:**
- Create: `src/world/ShiverDriver.tsx`
- Modify:
  - `src/world/wind.ts`: a shared `shiverWave = { strength: { value: 0 }, radius: { value: 0 } }` bound in `inWind` as `uShiver` and `uShiverRadius`, added to the `lean` and `sway` snippets and to the CPU swayers in `WindDriver`;
  - `src/world/World.tsx`: mount `<ShiverDriver />` in `Scene`, and add `data-shiver`.
- Test: `src/world/wind.test.ts`, `src/world/shiver.test.ts` (create), `e2e/barnaby.spec.ts`

**Interfaces, produced:**
- `shiverEnvelope(size: ShiverSize, t: number): { strength: number; radius: number }`, in `ShiverDriver.tsx`:
  - big: peak 1.6 over 2.0 s; small: peak 0.8 over 1.0 s;
  - `strength = peak * (1 - t / duration)` for `t` from 0 to the duration, and 0 after;
  - `radius = 14 * t` world units, measured from `HOUSE` (x −4.0, z −2.0).
- **The shader term:** `uShiver * exp(-pow(length(wp - houseXZ) - uShiverRadius, 2.0) / 4.5)`, added to the gust in `lean`, and to `sway`'s angle as a multiple of `amount`.
- `gustStart(seenAt: number | null, shiver: { at: number; size: ShiverSize } | null, now: number): number | null`: returns `shiver.at` when the shiver is new (`at !== seenAt`) and `now - at <= 3000`; otherwise `null`.
- **`ShiverDriver`:**
  - watches `characters.shiver.at`;
  - when `gustStart` returns a start, and motion isn't `still`, it plays the envelope from `t = 0` at the shiver's own size, restarting if a gust is already playing (never stacking);
  - it invalidates frames while the gust plays.
- **`data-shiver="<size>:<n>"`** on the world element, where `n` counts the shivers seen in this page session (empty before the first). It is updated even in still motion, so tests can run with reduced motion.

**Steps:**
