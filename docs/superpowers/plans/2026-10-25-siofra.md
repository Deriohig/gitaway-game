# Síofra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Síofra, the púca, becomes the second character.
- The hare is glimpsed in the journal before she's met.
- She's met at a morning once Barnaby has settled.
- After that, her moments (shapes, a notice, gifts) post every 2–3 days, and her figure at the meadow's field edge can be tapped for a line.
- The hare carries her name once she's met.

**Architecture:**
- Barnaby's generic pieces (morning stamping, the tap pool, the speaking window, the sanitize helpers) move into `src/game/systems/characterKit.ts`. Barnaby uses them unchanged.
- Síofra gets `characters.siofra` and `src/game/systems/siofra.ts`. Her step runs alongside Barnaby's inside the `characters` step.
- Her lines live in `src/game/content/siofra.ts`. Her figure is `src/world/features/Siofra.tsx`, on the meadow.

**Tech Stack:** TypeScript, React Three Fiber, zustand, vitest (`TZ=UTC vitest run`), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-25-siofra-design.md`. Read it first. Where this plan and the spec differ, the ruling below says why.

**Start condition:** execution begins only after `feat/letters` has merged into main. Then merge `origin/main` into `feat/siofra` with a merge commit (never rebase or force-push), because letters adds `barnabySettledAt` to `characters.ts` and `mail.ts`'s `NEEDS`.

## Global Constraints

## Rulings

- **S1, the tap-5 gate.**
  - **Decision:** tap line 5 (the duckling) needs `owned.duck > 0`.
  - **Why:** the lore gates it ("Tap 5 needs ducks", VOICES); the spec named only nap 2's cat.
  - **Cost if wrong:** one line plays later than it might.
- **S2, the gifts field's name.**
  - **Decision:** her field is `given: SiofraGiftId[]`.
  - **Why:** `GameState.gifts` already holds the cat and the dog.
  - **Cost if wrong:** none.
- **S3, the notice's gates.**
  - **Decision:** the crops-left-standing notice is judged on the plots as they are when the moment posts. A ripe crop is `crop !== null && readyAt !== null && readyAt <= post`; resting soil is a plot with `crop === null`.
  - **Why:** the state keeps no plot history.
  - **Cost if wrong:** after an absence, a moment may see slightly later plots than at 18:00.
- **S4, her name while characters is off.**
  - **Decision:** the hare's name lookup returns "Síofra" only while `characters` is on and she's met.
  - **Why:** with the switch off, she doesn't exist in the game.
  - **Cost if wrong:** none.
- **S5, composing the step.** `advanceCharacters` runs Barnaby's step and then hers, returning true if either changed anything, and `charactersDue` ORs both due checks. Barnaby's early return becomes his own function's return.
- **S6, the meeting's stored time.**
  - **Decision:** once everything she waits for holds, the meeting is stored as `characters.siofra.dueAt`, the next 06:00 local, as Barnaby's `dueAt` is. The meeting happens at it. It's only ever put back (to an earlier morning, when the clock has gone back and it's stale), never cleared.
  - **Why:** "the next 06:00 after now" worked out afresh each tick is always in the future, so the meeting would never arrive.
  - **Cost if wrong:** none beyond one saved field.

### Task 4: Her moments

**Files:**
- Modify: `src/game/systems/siofra.ts`, `src/game/systems/siofra.test.ts`

**Interfaces (produces):**
- `MOMENT_HOUR = 18`, `MOMENT_GAP_DAYS = [2, 3] as const`, `SHIVER_QUIET_MS`.
- **`momentDue(s: GameState): number | null`:**
  - before any moment, any 18:00 post once `(s.visitors.seen.hare ?? 0) >= 1`. The state keeps no time for the first visit, so the cursor `checkedAt` decides which post comes first;
  - after one, 18:00 on the local day `momentAt + gap`, where `gap` is 2 or 3, picked by an FNV-1a hash of `localDateKey(momentAt)`.
- **`momentPool(s: GameState, post: number): MomentLine[]`:**
  - **before she's met:** glimpses, plus shapes once any glimpse has posted. Empty while `isPresent(s, 'hare')` (from visitors.ts).
  - **after she's met:** shapes, plus the notice lines whose plot condition holds (S3), plus the gifts not yet given. Glimpses stop.
  - Shapes are gated by `ShapeNeed` against `owned`. The pool excludes `lastMoment`.
- **The moment step**, inside `advanceSiofra`:
  - it runs once the latest 18:00 at or before `now` (call it `post`) is ≥ `momentDue` and > `checkedAt`;
  - it sets `checkedAt = post`;
  - **shiver hold:** with `sh = characters.shiver`, if `post >= sh.at`, `post < sh.at + SHIVER_QUIET_MS` and `now < sh.at + SHIVER_QUIET_MS`, it waits without setting `checkedAt`. Once the window has passed (the same evening), the moment is stamped at `eventTime(s, Math.max(post, sh.at + SHIVER_QUIET_MS), now)`;
  - **one waits:** if any of her moment lines already has `at > seenAt`, it stops (only one waits);
  - otherwise it picks repeatably from the pool, using the hash of `localDateKey(post)` and `lastMoment`;
  - it writes the line at `eventTime(s, post, now)`: kind `visitor` before the meeting, `character` after;
  - it sets `momentAt` and `lastMoment`, and appends to `given` for a gift;
  - it never pushes to `out`.
